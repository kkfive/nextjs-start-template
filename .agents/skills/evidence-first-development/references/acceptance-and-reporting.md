# Acceptance and Reporting

任务中临时维护下列合同；除非用户明确要求，不把一次性任务状态写入 tracked 文档或 `.workflow/` 作为规范输入。

```text
任务类别：
目标行为：
非目标：
影响范围与直接消费者：
验收标准：
证据类型：
RED 命令/步骤、exit code 与失败原因：
GREEN 命令/步骤与结果：
回归范围与结果：
独立验收方式与结论：
残余风险：
```

## 验收原则

- 每条验收标准都能映射到测试、fixture、命令、浏览器/API 步骤或明确的人工判断。
- 自动化 RED 记录基线状态、命令和与目标行为一致的失败原因；最终以同一证据取得 GREEN。
- 高风险任务由未参与实现的 reviewer/verifier、真实浏览器/API 或用户复核。
- 机器不能可靠判断需求是否产品正确、视觉是否满意或未知风险是否穷尽；这些结论不得伪装成静态 gate。

## 交付摘要

最终简洁报告：实现的行为、RED/GREEN、workspace/消费者/全局回归、build/E2E、独立验收、未覆盖风险。不要只写“测试通过”，也不要声称零 bug。
