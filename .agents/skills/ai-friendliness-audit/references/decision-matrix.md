# 决策矩阵

| 问题 | 决策 |
|---|---|
| 违反后可由 AST、manifest、类型、lint、fixture 或命令确定 | **automate**；提示词只保留必要语义或规则 ID |
| 当前代码、manifest 或命令能更准确回答 | **delete** 易腐事实，运行时读取事实源 |
| 多处定义同一义务 | **rewrite** 为一个 owner；其他位置只保留触发或链接 |
| 需要业务意图、风险判断、用户体验或证据质量判断 | **keep**，压缩为可观察约束 |
| 没有真实触发场景、消费者或高后果 | **delete**，除非先取得反例证据 |
| 规则必要但触发不可靠 | **rewrite/automate** 路由，并用真实无提示任务验证 |

## 保留文本的最低形态

- 范围明确：何时、对什么生效。
- 结果可观察：另一主体能判断遵守与否。
- 只写独特信息：不重复机器 pattern、流程 owner 或代码事实。
- gotcha 说明触发条件、后果、动作与验证。

## 证据等级

1. 真实行为、编译、测试、浏览器/API 或结构化工具事件。
2. AST、manifest、filesystem 与独立 fixture。
3. 多 Agent 对同一代码事实的交叉判断。
4. 文本启发式与 token 估算。
5. 规则自述或 agent 自述（不能单独作为通过证据）。
