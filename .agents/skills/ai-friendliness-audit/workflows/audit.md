# 审计流程

1. **冻结基线**：记录治理文件、估算上下文、工作树状态和现有门禁；现有规则是审计对象，不是其自身保留依据。
2. **运行静态审计**：执行仓库脚本，分类确定性错误与启发式 warning。
3. **多 Agent 交叉检查**：至少分别审查机器替代、真实触发、语义重复和表述成本；结论必须引用代码或运行证据。
4. **分类决策**：按 decision matrix 为每项选择 keep、delete、automate 或 rewrite，并指定唯一 owner。
5. **先 RED 后修改**：新增机器检查先用独立 fixture 证明缺口；不得以 checker 自测或 AI 自述证明有效。
6. **精简与修复**：优先处理高频入口、重复 owner、时态事实和已被机器覆盖的细节。
7. **分层验证**：静态检查每次运行；真实触发、多 agent 或外部验收按成本定期运行。无法观测时报告限制，不推断通过。
8. **量化交付**：报告前后体量、findings、未机器化语义和未执行证据。

报告只描述当前状态，不把迁移过程写回长期规则。
